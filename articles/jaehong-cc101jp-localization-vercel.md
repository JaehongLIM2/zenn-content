社内で生成AIやClaude Codeを使い始める人が少しずつ増えていました。

しかし、最初につまずく場所はAIへの質問方法だけではありませんでした。PowerShellを開き、コマンドを入力し、表示されたメッセージを読むところで止まってしまう人もいます。公式ドキュメントを案内するだけでは、最初の一歩を支えるには情報量が多いとも感じました。

そこで、Claude Codeの基本概念やコマンドを日本語で確認できる教材を用意し、社内で共有することにしました。完成したサイトとソースコードは次の場所で公開しています。

- [CC101 日本語版](https://cc101jp.vercel.app/ja)
- [GitHub: im-jaehong/cc101jp](https://github.com/im-jaehong/cc101jp)

この記事では、教材を一から作らず既存のガイドを日本語化した理由、AIを使った翻訳と検証の流れ、Vercelを選んだ判断、実際に社内で使って分かったことを整理します。

## 最初の課題は「使い方」より「始め方」だった

Claude Codeはターミナルから利用します。開発者には自然でも、普段コマンドラインを使わない人にとっては、PowerShellを操作すること自体が最初の壁になります。

社内では、次のような内容を一か所で確認できる資料が必要でした。

- Claude Codeが何をするツールなのか
- インストールと認証をどう進めるのか
- 最初に覚えるコマンドは何か
- Permission、Context、CLAUDE.mdなどの用語は何を意味するのか
- 問題が起きたときにどこを確認するのか

全員にすべての機能を覚えてもらうことが目的ではありません。分からなくなったときに日本語で戻って確認できる場所を作り、導入初期の負担を下げることを目標にしました。

## Instagramで見つけたCC101を基にした理由

教材の構成を調べていたとき、Instagramで韓国語の[CC101](https://github.com/fivetaku/cc101)を知りました。

CC101は、入門者向けに内容が段階的に整理され、画面も読みやすく作られていました。公式ドキュメントの内容をそのまま並べるのではなく、「次に何を学べばよいか」が見える構成です。この点が、今回の目的に合っていると判断しました。

一から似た教材を作るより、優れた既存資料を基に日本語対応を追加し、更新可能な形で公開する方が早く利用者へ届けられます。一方で、公開されているリポジトリだから無条件に再利用できるわけではありません。原著者のクレジット、ライセンスへのリンク、日本語対応という変更内容の明示を、翻訳とは別の作業として確認する必要があります。

公開後の見直しでは、READMEとLICENSEの表記が一致していないことも分かりました。そこで、どちらか都合のよい方を選ぶのではなく、より保守的なCC BY-NC 4.0を基準にしました。`LICENSE`では原著と改変部分を分け、`ATTRIBUTION.md`には原著者、出典、変更内容、非公式な改変版であることを記録しています。社内利用のようにNonCommercialの判断が分かれ得る用途は、許可されたと断定せず、原著者への確認事項として残しました。

## 4段階で翻訳と検証を進めた

日本語版では、21個のMarkdownファイルに加えて、メニュー、説明文、バッジなどのUI文言も日本語化しました。

一度のAI翻訳だけで公開せず、次の4段階で確認しました。

1. Claudeで韓国語から日本語への初回翻訳
2. ChatGPTで文章を再確認し、必要な箇所を再翻訳
3. Claudeでもう一度、用語と文脈の一貫性を確認
4. 最後に自分で読み直し、同僚にも軽く操作してもらう

異なるモデルを使ったのは、最初の翻訳に引きずられたまま同じ誤りを残す可能性を減らすためです。ただし、複数のAIが同じ回答をしても、その内容が正しいとは限りません。

特に次の項目は、人が最終的に確認しました。

- コマンド、オプション、ファイル名を翻訳していないか
- Claude Code固有の用語がページごとに揺れていないか
- 日本語として読めても、元の技術的な意味が変わっていないか
- 初心者が手順を実行するとき、前提条件が抜けていないか
- PowerShell利用者にも意味が伝わる説明になっているか

この作業で、翻訳は単語を置き換える作業ではなく、読者が同じ操作を再現できるように文脈を移す作業だと分かりました。

## Next.jsへ日本語ルートを追加した

元のサイトはNext.jsのApp Router、TypeScript、Tailwind CSSで構成されています。日本語コンテンツを追加するだけでなく、`/ja`で日本語版を表示できるように言語ルートも拡張しました。

対応言語を定義し、ビルド時に各言語のルートを生成します。

```ts
const SUPPORTED_LANGS = ['ko', 'en', 'ja'] as const

export function generateStaticParams() {
  return [
    { lang: 'ko' },
    { lang: 'en' },
    { lang: 'ja' },
  ]
}
```

コンテンツの対応では、主に次の変更を行いました。

- `content/ja`へ日本語Markdownを追加
- セクション定義へ`title_ja`、`description_ja`、`file_ja`を追加
- 日本語メタデータを追加
- 初回表示を日本語へ変更
- 日本語、韓国語、英語を個別に選べる言語切り替えを追加
- フッターへ原著者と元プロジェクトのクレジットを追加

日本語ファイルだけを増やすのではなく、コンテンツの読み込み、ナビゲーション、メタデータまで同じ言語でつながるようにする必要がありました。

## AWSではなくVercelを選んだ理由

このサイトには、データベース、常時動作するAPI、独自のネットワーク構成は必要ありません。主な要件は、Next.jsで作られた教材を軽く公開し、修正内容をすぐ反映できることでした。

AWSでも公開できますが、今回の規模では構築・管理する範囲が広くなります。社内サーバーへ置く方法もありましたが、せっかくなら未経験のサービスを試し、公開までの流れも学びたいと考えました。

そこで、Next.jsとの連携が分かりやすく、GitHubリポジトリからデプロイできるVercelを選びました。

```text
GitHubへpush
    ↓
Vercelでビルド・デプロイ
    ↓
https://cc101jp.vercel.app/ja
```

今回の判断で重視したのは、サービスの機能数ではなく、要件に対して管理対象を増やし過ぎないことです。教材の更新が中心なら、インフラ構築よりコンテンツとレビューへ時間を使える構成が適しています。

ただし、VercelのHobbyプランは非商用の個人利用向けです。会社の業務として運用する場合は、アクセス量が少なくてもProなど利用目的に合うプランが必要です。コンテンツのライセンスとホスティングサービスの利用条件は別の問題なので、それぞれ確認しなければなりません。

## 社内で使って分かったこと

公開した資料が、すべての人に最初から最後まで100%利用されたわけではありません。

それでも導入初期には、メンバーがサイトを見ながらコマンドを確認したり、Claude Codeの基本概念を調べたりする場面がありました。毎回同じ説明を一から行うのではなく、「まずここを確認してください」と共有できる場所ができたことに意味がありました。

教材の価値は、全ページを読んでもらうことだけでは測れません。最初の操作で止まる人を減らすこと、質問する前に自分で確認できること、共通の用語で会話できることも導入支援の成果です。

一方、利用状況を数値では記録していなかったため、「どれだけ効率が上がったか」までは断定できません。今後同じ取り組みを行うなら、よく参照されたページ、質問が減った項目、利用者からの修正要望を記録したいと考えています。

## この取り組みから学んだこと

### 1. 導入の障害は機能不足とは限らない

便利なツールでも、ターミナル、言語、専門用語が最初の障害になります。新しい機能を追加する前に、利用者がどこで止まっているかを観察することが重要でした。

### 2. AI翻訳にも役割分担が必要

Claudeで初稿を作り、ChatGPTで別の観点から確認し、再度Claudeと人が検証する流れは、長い技術資料を扱ううえで有効でした。ただしAI同士の一致を正解とはせず、コマンドと仕様は公式ドキュメントで確認する必要があります。

### 3. デプロイ先は、管理したい範囲から選ぶ

AWS、社内サーバー、Vercelのどれが常に優れているという話ではありません。今回のような静的コンテンツ中心のサイトでは、Vercelへ任せられる部分を増やし、教材の改善へ集中する判断が合っていました。

### 4. 公開はデプロイ成功で終わらない

既存プロジェクトを基にすると、ライセンス表記、原著者のクレジット、OG画像、ドメイン、アクセス解析IDなども引き継がれます。画面が表示された時点を完成とせず、公開先に合わせて設定と権利関係を点検する必要がありました。

### 5. 小さく公開すると、次の改善点が見える

最初から完全な研修システムを作るのではなく、参照できるサイトとして公開したことで、言語切り替え、表現の修正、情報更新など、利用後に必要な改善が見えるようになりました。

## 今後改善したいこと

- Claude Codeの更新に合わせ、各ページの確認日を記録する
- 日本語の用語集を作り、ページ間の表記を統一する
- ライセンス、クレジット、Vercelのプラン条件を定期的に確認する
- メタデータ、`html`の`lang`属性、OG画像を言語ごとに確認する
- アクセス解析を利用する場合は、所有者とプライバシー方針を明確にする
- 社内利用者から質問と改善要望を集める

## まとめ

この取り組みでは、韓国語のClaude Codeガイドへ日本語対応を追加し、Vercelで公開して社内の導入資料として利用しました。

技術的には、Next.jsの多言語対応とVercelへのデプロイが中心です。しかし、実際に重要だったのは、利用者が最初に止まる場所を見つけ、既存の優れた資料を活用し、AIと人のレビューを組み合わせて、使える状態まで届けることでした。

「新しいシステムを作る」ことだけが問題解決ではありません。必要な人が使える形に整え、公開し、利用後の改善につなげることも開発の一部だと学びました。
